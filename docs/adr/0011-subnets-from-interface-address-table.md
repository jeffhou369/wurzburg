# 網段來自交換器的介面位址表，不從 ARP 推導

PRD 的 ADR-002 從 ARP 裡的主機位址推導網段，但 ARP 沒有遮罩，推導必然不準，只能靠系統管理員修正。目標環境的 L3 閘道全部在 ARP 來源交換器上，所以交換器的介面位址表裡就有每個網段確切的位址與遮罩。我們決定每一輪除了 ARP 表，也讀同一個 VRF 的介面位址表，以介面上實際設定的網段作為發現的網段；系統不從主機位址推測遮罩。

## 考慮過的做法

- **從 ARP 的主機位址以啟發式推導**（PRD 原案）：不必多讀一張表，但 `/23`、`/25` 這類網段一定會切錯。
- **完全手動建立**：沒有誤判，但違反「先掃出所有網段再勾選」的需求，也容易漏段。

## 後果

- 每筆 VRF 讀取設定每一輪多讀一張小表。
- 新增的 VLAN 會自動以待檢視的網段出現。
- 系統因此確切知道哪些位址是交換器自己的閘道位址，這些位址不建立 IP 紀錄。HSRP／VRRP 的虛擬位址不在介面位址表裡，仍照一般位址處理。
- ARP 觀測對不到任何網段時進入未定前綴，正常情況下應該很少。
- 閘道不在 ARP 來源交換器上的網段不會被發現，只能手動新增。
- 介面位址表在 IOS-XE 與 NX-OS 上的實際行為（尤其 secondary 位址）尚待實機驗證。
- PRD ADR-002 的其餘內容仍然有效：新發現的網段不自動納管，DHCP 與無線只靠手動標記排除，系統管理員可手動新增與修正網段。
