# 一個園區一套部署，IPv4 在系統內唯一

不同園區可能使用相同的私有 IP，同一個園區內不同 VRF 的位址則不重疊。我們決定一個園區安裝一套 Würzburg，各有自己的資料庫，並以 IPv4 位址本身作為 IP 紀錄的身分；不做多租戶、不做跨園區的統一管理，也不支援重疊的位址空間。這樣 IP 紀錄、登記、通知去重鍵與郵件連結都不必帶上「位址空間」，模型與介面簡單很多。

## 考慮過的做法

- **單一部署管理多個園區**：所有資料表與權限判斷都要帶園區，位址重疊也得處理。目前沒有跨園區統一管理的需求，成本遠高於效益。
- **以「VRF + IP」作為身分**：能支援重疊的位址空間，但目標環境的 VRF 位址不重疊，這會讓每一處都多一個用不到的維度。

## 後果

- 「園區內 IPv4 不重疊」是部署前提條件，要寫進安裝文件。
- 每筆 ARP 觀測仍保留它來自哪台交換器的哪個 VRF，衝突的詳細資料也會顯示。萬一某個園區實際上有重疊的位址，會表現為持續存在的衝突，系統管理員看得出原因，日後要遷移時也有資料可用。
- 日後若要支援重疊位址或跨園區管理，是主鍵層級的變更，需要新的 ADR。
