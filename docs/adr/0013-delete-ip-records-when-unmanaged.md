# 位址離開管理範圍時，直接刪除 IP 紀錄

PRD 的原則是不靜默刪除（FR-13），Q-17 的 SA 建議是取消納管後把 IP 紀錄隱藏、保留登記與歷史，重新納管時恢復。我們決定：網段改為不納管，或位址被劃入排除範圍時，IP 紀錄連同它的衝突與通知去重狀態直接刪除。理由是不在管理範圍內的東西就不該留在系統裡，「不納管」要名副其實，也不必多維護一種「封存」狀態與它在儀表板、匯出、通知中的各種例外。

## 考慮過的做法

- **封存**（PRD 的 SA 建議）：保留紀錄但停止更新並隱藏，重新納管時恢復。誤操作可以完全復原，但多一種狀態。
- **隱藏但繼續更新**：等於持續追蹤系統管理員明確說不要管的位址。

## 後果

- 刪除不可復原，產品也不做備份。因此儲存前要顯示確認對話框，寫明將刪除幾筆、其中幾筆有擁有者。
- 稽核紀錄是唯一能回頭查的地方：有擁有者的 IP 紀錄逐筆記下 IP、MAC、擁有者、擁有者信箱與到期日。
- 重新納管後，位址以全新的未登記 IP 紀錄出現，並在下一次未登記彙整中列為新增。
- 這不影響「離線不等於刪除」：有擁有者的 IP 紀錄離線多久都保留。未登記且離線過久的 IP 紀錄另有自動清除的規則，見開發規格第 3.7 節。
