## 問題陳述

園區裡的 IPv4 位址實際上由誰在用，只有交換器的 ARP table 知道；而「這個位址該由誰負責」只存在於試算表或人的記憶裡。兩者長期脫節，造成幾個反覆出現的問題：

- 登記仰賴人工填寫，裝置上線、搬遷、汰換或人員離職後沒有人更新，對帳很花時間。
- 在線卻沒有人負責的位址，要等出事才被發現。
- 裝置暫時關機或離開時，如果把紀錄刪掉，擁有者、備註與到期資訊就跟著消失。
- 一個位址被兩台裝置同時使用，或被別人拿去用，沒有任何機制會提醒。
- 網管是唯一能維護清冊的人，所有登記工作都落在他身上；但真正知道裝置是誰的，是使用裝置的人。
- 園區的網路是隔離的，不能依賴外部服務查詢廠商資訊；交換器與 SNMP 的設定又必須在目錄服務故障時仍然改得了。

## 解決方案

Würzburg 讓交換器的 ARP table 成為清冊的來源，把登記這件事交還給使用裝置的人。

- 系統每 3 分鐘讀取園區內各 ARP 來源交換器的 ARP table，為納管網段內的每個位址自動維護一筆 IP 紀錄，並顯示它是在線還是離線。
- 網段由系統從交換器上讀出來，系統管理員只需要決定每個網段要納管還是不納管，並在需要時劃出排除範圍。
- 一般使用者用組織帳號登入，在一頁式的工作臺上找到自己的裝置並完成登記，成為擁有者；登記一年後系統會寄信請擁有者重新確認。
- 系統每小時把新出現的在線且未登記的位址彙整寄給系統管理員，每週再寄一封仍未登記的總表。
- 同一個位址出現兩個 MAC，或有擁有者的位址換了 MAC 時，系統開一筆衝突讓系統管理員裁決，不會自動覆蓋。
- 系統管理員使用內建帳號，不依賴 AD 或 RADIUS；第一次登入後由設定精靈帶著完成初始設定。
- 一個園區安裝一套，以 Docker Compose 部署，廠商查詢只用本地資料。

## 使用者故事

### 安裝與首次啟動

1. 身為安裝人員，我想要用一份 Compose 設定就把應用程式與資料庫啟動起來，以便在園區的一台主機上快速完成安裝。
2. 身為安裝人員，我想要在環境變數裡指定第一個系統管理員的帳號與初始密碼，以便系統不必帶著預設密碼出貨。
3. 身為系統管理員，我想要在第一次登入時被要求修改密碼，以便留在設定檔裡的初始密碼不會被長期使用。
4. 身為安裝人員，我想要在已經有系統管理員之後，那兩個環境變數不再有任何作用，以便重新啟動容器不會意外重設密碼。
5. 身為安裝人員，我想要一份選用的 HTTPS 範例設定，以便用組織的憑證加密連線。
6. 身為登入的人，我想要在連線沒有加密時於登入頁看到明文傳輸的警告，以便知道輸入帳密的風險。
7. 身為安裝人員，我想要安裝文件列出部署前提條件，以便在安裝前確認這個園區適用。
8. 身為維運人員，我想要一個不含任何 secret 的健康檢查端點，以便監控系統是否存活。
9. 身為維運人員，我想要應用程式把結構化日誌寫到標準輸出，以便用容器的日誌工具查看。
10. 身為系統管理員，我想要在忘記密碼時能在主機上以管理指令重設，以便不依賴郵件也能救回帳號。
11. 身為安裝人員，我想要資料庫結構在應用程式啟動時自動更新到正確版本，以便升級時不必手動執行指令。

### 設定精靈

12. 身為系統管理員，我想要在第一次登入並改完密碼後自動進入設定精靈，以便知道一套新系統需要設定哪些東西。
13. 身為系統管理員，我想要在精靈中設定園區的顯示名稱與時區，以便介面、郵件與排程符合這個園區。
14. 身為系統管理員，我想要在精靈中選擇 AD 或 RADIUS 作為驗證來源並填入連線資料，以便一般使用者能用組織帳號登入。
15. 身為系統管理員，我想要用一組帳密當場測試驗證來源，以便在離開這一步之前確認設定正確。
16. 身為系統管理員，我想要在精靈中設定 SMTP 與系統管理員收件清單並寄出測試信，以便確認通知寄得出去。
17. 身為系統管理員，我想要在精靈中新增第一台交換器與它的 VRF 讀取設定並測試讀取，以便確認 SNMP 設定正確。
18. 身為系統管理員，我想要在精靈的最後一步檢視剛發現的網段並決定納管或不納管，以便管理表開始有資料。
19. 身為系統管理員，我想要精靈的每一步都可以稍後再設定，以便在某樣東西還沒準備好時不會卡住安裝。
20. 身為系統管理員，我想要在首頁看到「尚未完成的設定」清單與各項的後果，以便知道系統還缺什麼。
21. 身為系統管理員，我想要未完成清單提醒我尚未啟用 HTTPS，以便這件事不會被遺忘。
22. 身為系統管理員，我想要從設定頁重新開啟精靈，以便之後補完跳過的步驟。

### 交換器與 VRF 讀取設定

23. 身為系統管理員，我想要新增、編輯、停用與刪除 ARP 來源交換器，以便決定系統從哪些設備讀取 ARP table。
24. 身為系統管理員，我想要為交換器指定平台是 IOS-XE 還是 NX-OS，以便系統用正確的方式解讀它的回應。
25. 身為系統管理員，我想要為交換器加上一個顯示用的標籤，以便在清單上分辨它的角色。
26. 身為系統管理員，我想要為一台交換器設定多筆 VRF 讀取設定，以便讀到每個 VRF 的 ARP table。
27. 身為系統管理員，我想要在使用 SNMP v3 時為每個 VRF 填入 context 名稱，以便用同一組憑證讀取不同的 VRF。
28. 身為系統管理員，我想要在使用 SNMP v2c 時為每個 VRF 填入專屬的 community，以便在沒有 v3 的設備上也讀得到各 VRF。
29. 身為系統管理員，我想要在沒有設定額外的 VRF 時看到資料可能不完整的提示，以便知道 VRF 內的位址不會被看到。
30. 身為系統管理員，我想要 SNMP 憑證在儲存後不再顯示，以便憑證不會從畫面外洩。
31. 身為系統管理員，我想要手動觸發立即同步，以便改完設定後馬上看到結果。
32. 身為系統管理員，我想要看到每一筆 VRF 讀取設定最近一次讀取的時間、結果、筆數與錯誤類別，以便判斷是哪裡出了問題。
33. 身為系統管理員，我想要一筆 VRF 讀取設定失敗時不影響其他的，以便一台設備出問題不會讓整個園區的資料停擺。
34. 身為系統管理員，我想要讀取失敗時保留上一次成功的狀態，以便位址不會因為暫時的連線問題被誤判為離線。
35. 身為系統管理員，我想要在一輪輪詢來不及完成時於介面看到提示，以便知道資料可能比平常舊。
36. 身為系統管理員，我想要停用一台交換器後，只有它看得到的位址變成離線，以便資料反映實際的來源。

### 網段

37. 身為系統管理員，我想要系統自動列出交換器上設定的網段，以便不必自己輸入每一個 CIDR。
38. 身為系統管理員，我想要新發現的網段以待檢視的狀態出現並在側欄顯示數量，以便不會有網段從來沒人看過。
39. 身為系統管理員，我想要把網段設為納管，以便它的位址開始出現在管理表裡。
40. 身為系統管理員，我想要把網段設為不納管並選擇原因，以便日後看得出這是誰基於什麼理由做的決定。
41. 身為系統管理員，我想要在納管的網段裡劃出排除範圍，以便同一個網段裡的 DHCP 發放範圍不會塞滿未登記的清單。
42. 身為系統管理員，我想要手動新增網段，以便處理系統沒有自動發現的情況。
43. 身為系統管理員，我想要修正網段的 CIDR，以便更正錯誤。
44. 身為系統管理員，我想要在網段的詳細資料中看到閘道位址，以便知道哪些位址是交換器自己的。
45. 身為系統管理員，我想要閘道位址不出現在管理表與未登記的通知裡，以便安裝完不會被幾百筆閘道位址淹沒。
46. 身為系統管理員，我想要看到一份未定前綴的清單，以便發現不屬於任何已知網段的位址並為它們建立網段。
47. 身為系統管理員，我想要交換器上已經不存在的網段被標示出來而不是自動刪除，以便由我決定怎麼處理。
48. 身為系統管理員，我想要在網段的變更會刪除 IP 紀錄時先看到將刪除幾筆、其中幾筆有擁有者，以便不會在不知情下刪掉大量登記。
49. 身為系統管理員，我想要必須再次確認才真正執行刪除，以便誤觸不會造成損失。

### IP 紀錄與在線狀態

50. 身為登入的人，我想要納管網段內被交換器看到的位址自動出現在管理表，以便不必有人手動建立。
51. 身為登入的人，我想要看到每個位址是在線還是離線，並且以文字標示，以便不靠顏色也能判讀。
52. 身為登入的人，我想要離線的位址以灰階顯示但仍保留在表中，以便擁有者與備註不會因為裝置關機而消失。
53. 身為登入的人，我想要在畫面上看到「在線」的確切意思與它的延遲，以便理解為什麼剛關機的裝置還顯示在線。
54. 身為登入的人，我想要看到位址最近在哪些交換器、哪個 VRF、哪個介面上被看到，以便知道它接在網路的哪裡。
55. 身為登入的人，我想要看到位址的廠商名稱，以便大致判斷它是什麼設備。
56. 身為登入的人，我想要在查不到廠商時看到「未知」，以便知道那不是資料載入失敗。
57. 身為登入的人，我想要看到位址的首次與最近見到時間，以便判斷它存在多久。
58. 身為登入的人，我想要看到位址的變更歷程（MAC 變更、在線與離線的切換），以便追查發生過什麼事。
59. 身為系統管理員，我想要未登記且離線很久的 IP 紀錄被自動清除，以便管理表不會累積沒有意義的紀錄。
60. 身為系統管理員，我想要設定自動清除的天數或把它停用，以便配合這個園區的做法。

### 首頁工作臺

61. 身為登入的人，我想要在首頁上半部看到納管總數、在線、離線、未登記、已到期與衝突的數字，以便一眼掌握現況。
62. 身為登入的人，我想要看到最近一次同步的時間與是否成功，以便知道資料有多新。
63. 身為登入的人，我想要以 IP、MAC、擁有者、主機名稱或備註搜尋，以便快速找到某一筆。
64. 身為登入的人，我想要以網段、交換器、在線狀態、登記狀態、衝突與到期篩選，以便只看關心的位址。
65. 身為登入的人，我想要表格分頁與排序，以便在兩萬多筆的規模下仍然流暢。
66. 身為登入的人，我想要狀態以組合文字呈現（例如「在線 · 未登記」），以便同時看到多個面向。
67. 身為登入的人，我想要 IP、MAC 與時間以等寬字顯示，以便對齊與比對。
68. 身為登入的人，我想要一鍵複製某一筆的 IP，以便貼到別的工具。
69. 身為登入的人，我想要把目前篩選的結果匯出成 Excel，且狀態是文字，以便離線整理或交給別人。
70. 身為登入的人，我想要即將到期的登記在表格上有標示並可篩選，以便提早處理。

### 登記

71. 身為一般使用者，我想要登記一筆未登記的 IP 紀錄並立即成為擁有者，以便不必等任何人核准。
72. 身為一般使用者，我想要在使用 AD 時擁有者信箱自動帶入我的信箱，以便少填一個欄位。
73. 身為一般使用者，我想要把擁有者信箱改成共用信箱，以便到期催認寄到團隊都看得到的地方。
74. 身為一般使用者，我想要在信箱格式錯誤時立刻被提示，以便催認信不會寄不到。
75. 身為一般使用者，我想要填寫裝置類型、主機名稱與備註，以便別人看得懂這個位址是什麼。
76. 身為一般使用者，我想要在備註欄旁看到「所有登入者都看得到」的說明，以便不會寫入敏感內容。
77. 身為擁有者，我想要編輯自己的登記，以便資料保持正確。
78. 身為擁有者，我想要重新確認自己的登記，以便有效期再延長一年。
79. 身為擁有者，我想要釋放不再使用的位址，以便它回到未登記。
80. 身為一般使用者，我想要看到別人登記的擁有者與擁有者信箱，以便找到某個位址的負責人並聯絡他。
81. 身為一般使用者，我想要在開啟別人的登記時看到唯讀畫面與聯絡系統管理員的說明，以便知道為什麼不能改。
82. 身為系統管理員，我想要替別人登記並指定擁有者，以便處理使用者無法自己登記的設備。
83. 身為系統管理員，我想要把一筆登記改派給另一個帳號，以便處理人員異動。
84. 身為系統管理員，我想要釋放任何一筆登記，以便修正錯誤的登記。

### 批次操作

85. 身為登入的人，我想要在表格上勾選多筆，以便一次處理多個位址。
86. 身為登入的人，我想要一次勾選目前篩選結果的全部，以便不必逐頁勾選。
87. 身為一般使用者，我想要批次登記多筆未登記的 IP 紀錄並套用同一組欄位值，以便不必重複填寫幾十次。
88. 身為擁有者，我想要批次重新確認多筆登記，以便一封合併的催認信只需要處理一次。
89. 身為擁有者，我想要批次釋放多筆登記，以便汰換一批設備時一次完成。
90. 身為系統管理員，我想要批次改派多筆登記，以便有人離職時一次轉交。
91. 身為登入的人，我想要在批次操作後看到哪些成功、哪些沒有成功與原因，以便知道還有什麼要處理。

### 到期

92. 身為擁有者，我想要在登記到期前 14 天收到提醒，以便有時間處理。
93. 身為擁有者，我想要在到期當天再收到一次通知，以便不會錯過。
94. 身為擁有者，我想要同一天到期的多筆登記合併在一封信裡，以便信箱不被洗版。
95. 身為擁有者，我想要信中的連結帶我到待確認的清單，以便直接處理。
96. 身為擁有者，我想要信中的連結必須登入後才能變更任何東西，以便信被轉寄時不會被別人修改我的登記。
97. 身為系統管理員，我想要到期後的復催有次數上限，以便系統不會無止境寄信。
98. 身為系統管理員，我想要只在最後一次復催時收到副本，以便我收到的每一封都真的需要我處理。
99. 身為系統管理員，我想要沒有回應的登記維持已到期並保留擁有者與備註，以便我能判斷要改派還是釋放。
100. 身為系統管理員，我想要調整有效期、提前天數、復催間隔與次數，以便符合這個園區的政策。

### 衝突

101. 身為系統管理員，我想要同一個位址同時出現兩個以上的 MAC 時系統開一筆衝突，以便我知道有裝置在搶同一個位址。
102. 身為系統管理員，我想要有擁有者的位址換了 MAC 時系統開一筆衝突而不是自動更新，以便登記不會被默默指到別人的裝置上。
103. 身為系統管理員，我想要未登記的位址換了 MAC 時系統直接更新，以便衝突清單裡只有真正需要裁決的項目。
104. 身為系統管理員，我想要多台交換器回報同一個位址與同一個 MAC 時不被當成衝突，以便備援的核心不會製造假警報。

## 實作決定

### 架構

- 後端是 Go（ADR 0010）。排程器、API 與前端靜態檔在同一個行程、同一個 `app` 容器。資料庫是 MariaDB，只在 Compose 的內部網路。
- 前端是 Angular；元件自己寫，行為以 Angular CDK 為基礎，不用 Angular Material 或其他元件庫的外觀（ADR 0014）。
- 前後端以 REST 加 JSON 溝通，一份 OpenAPI 描述檔是唯一的契約；前端的 API 型別由它產生。
- 單一倉庫，分成後端、前端與部署設定三個區塊。
- 一個園區一套部署，IPv4 位址是 IP 紀錄的身分（ADR 0009）。
- 預設 HTTP，另附選用的 HTTPS 反向代理範例。
- 實際採用的程式庫與版本在開發前查過最新文件後確定。

### 模組

每個模組對外的介面要小，內部可以複雜。

| 模組 | 職責 | 對外介面 |
| --- | --- | --- |
| 採集 | 對一筆 VRF 讀取設定做 SNMP 讀取，封裝 v2c／v3 與兩個平台的差異 | 輸入一筆 VRF 讀取設定；輸出 ARP 觀測、介面位址、介面名稱，或一個錯誤類別 |
| 輪詢排程 | 每 3 分鐘啟動一輪；並行上限、同一台交換器一次一筆、重試一次、不重疊啟動；記錄每次讀取的結果 | 啟動一輪；立即同步；查詢輪詢狀態 |
| 管理範圍 | 維護網段、排除範圍、閘道位址與未定前綴；回答「這個位址該不該有 IP 紀錄」；計算一項變更會刪除哪些 IP 紀錄 | 套用一輪的介面位址；變更網段狀態或排除範圍（先預覽、再確認）；查詢位址的歸屬 |
| 狀態整併 | 把一輪的 ARP 觀測整併進 IP 紀錄：建立、在線與離線、採信 MAC、開衝突與自動已解消、變更事件、自動清除 | 套用一輪的讀取結果 |
| 登記 | 登記、編輯、重新確認、釋放、改派，單筆與批次；逐筆的權限判斷 | 對一組 IP 紀錄執行一個登記動作，回傳逐筆的結果 |
| 衝突裁決 | 三種裁決與處理中的規則 | 對一筆衝突套用一個裁決 |
| 通知 | 三種信的挑選、去重狀態、HTML 與純文字的產生、寄送、重試與紀錄 | 執行某一種信的到期工作；重設一個位址的通知狀態 |
| 驗證與工作階段 | AD、RADIUS、系統管理員本機帳號、鎖定、工作階段、帳號的自動建立 | 以某一條路徑驗證一組帳密；建立、查驗與撤銷工作階段 |
| 設定與 secret | 第 10 節的設定值；secret 的加密保存與不回顯 | 讀寫設定；測試一項外部連線 |
| 稽核 | 記錄與查詢 | 寫入一筆稽核；查詢 |
| OUI | 本地資料的匯入與查詢 | 以 MAC 查廠商；匯入資料檔 |
| 匯出 | 把一個查詢結果產生成 Excel | 以篩選條件產生檔案 |
| 時鐘 | 提供目前時間 | 所有與時間有關的邏輯都經由它取得時間，不直接讀系統時間 |

- 採集模組是唯一知道 SNMP 與平台差異的地方。實機的回應與測試資料不同時，只修改這個模組。
- 管理範圍與狀態整併是規則最密集的兩個模組，所有規則見開發規格第 3 節。
- 時鐘做成可替換的，是為了讓測試能控制時間（到期、復催、離線判定、自動清除、每小時與每週的排程）。

### 資料

建議的資料表（非正式 schema，名稱可調整）：`switches`、`vrf_read_configs`、`poll_runs`、`subnets`、`subnet_gateways`、`exclusion_ranges`、`ip_records`、`arp_sightings`、`ip_events`、`ip_conflicts`、`users`、`sessions`、`oui_entries`、`oui_imports`、`notification_logs`、`notification_states`、`audit_logs`、`settings`。

- `ip_records` 以 IPv4 位址唯一。
- `arp_sightings` 是「IP 紀錄 × VRF 讀取設定」目前的觀測，帶 MAC、介面、ARP 類型、最後見到時間與未見輪數；它是在線狀態與衝突判定的依據。
- 只保存目前的狀態與變更事件，不保存每一輪的完整觀測。
- 網段只有一個狀態欄位（待檢視、納管、不納管），不納管時必有原因。
- 擁有者是對 `users` 的參照；擁有者信箱是登記上的獨立欄位。
- 時間一律以 UTC 儲存。
- 資料庫結構以有版本編號的 SQL 檔管理，應用程式啟動時自動套用。
- 每一輪的整併以批次寫入。

### API

- 資源：工作階段（兩條登入路徑、登出）、目前的使用者、設定精靈的狀態、園區設定、驗證來源設定與測試、郵件設定與測試、交換器、VRF 讀取設定、同步（立即同步、輪詢狀態）、網段、排除範圍、未定前綴、IP 紀錄（查詢、變更事件、匯出）、登記動作、衝突（查詢、裁決）、通知紀錄與通知狀態的重設、OUI、稽核紀錄、系統管理員帳號、健康檢查。
- 清單一律由伺服端分頁、排序與篩選；表格與匯出共用同一組篩選條件。
- 會刪除 IP 紀錄的變更分成兩步：先預覽（回傳將刪除的筆數與其中有擁有者的筆數），再確認執行。
- 批次的登記動作接受一組 IP 紀錄（或「目前篩選結果的全部」），回傳逐筆的成功或失敗與原因；單筆是它的特例。
- 授權在每個請求、每一筆資料上判斷。未登入回 401，沒有權限回 403，輸入不合法回 422，狀態不允許該動作回 409。
- 變更類的請求防 CSRF；登入有速率限制。
- 任何回應都不包含 secret；設定類的回應只說明某個 secret「已設定」。

## 測試決定

### 什麼是好的測試

- 只驗證從外部觀察得到的行為：API 的回應、寄出的信、匯出的檔案。不檢查內部的函式、資料表內容或模組之間的呼叫。
- 測試的名稱與情境使用 `CONTEXT.md` 的名詞，讀起來像開發規格裡的一條規則。
- 內部重構而行為不變時，測試不需要修改。

### 測試接縫

**主要接縫：整個應用程式的對外邊界。** 把應用程式整個組起來，外部系統換成模擬器，資料庫用真的 MariaDB。

| 方向 | 做法 |
| --- | --- |
| 輸入 | HTTP API |
| 輸入 | SNMP 模擬器回放測試資料檔 |
| 輸入 | 模擬的 AD 與 RADIUS |
| 輸入 | 測試控制的時鐘，以及「執行一輪輪詢」「執行到期的通知工作」的觸發 |
| 檢查 | HTTP API 的回應，包含匯出的 Excel |
| 檢查 | 測試用郵件伺服器收到的信：收件人、主旨、HTML 與純文字兩部分 |

開發規格第 3 到 7 節的規則都在這個接縫驗證。至少涵蓋：

- 網段的發現與三種狀態、排除範圍、閘道位址、未定前綴。
- IP 紀錄的建立；刪除的預覽、確認與稽核明細。
- 多來源的在線判定、離線判定輪數、讀取失敗的輪次不計。
- 衝突的三種情況、三種裁決、處理中、自動已解消。
- 登記的權限（包含 403）、批次的逐筆結果。
- 到期催認的完整時程、合併、最後一次副本。
- 未登記彙整的去重、未登記總表、寄送失敗不標為已通知。
- 兩條登入路徑、鎖定、工作階段逾時、最後一個系統管理員不可停用。
- 首次啟動的帳號建立與強制改密碼、設定精靈的狀態與未完成清單。
- secret 不出現在任何 API 回應、日誌與郵件。
- 每種信都是 `multipart/alternative`、純文字與 HTML 資訊對等、使用者輸入的文字已跳脫。

前端不另開接縫：以瀏覽器在同一套環境走少數關鍵流程——登入、設定精靈、登記、批次重新確認、裁決衝突、把網段改為不納管的確認流程。

**輔助接縫：採集模組的輸出。** 輸入一份測試資料檔，檢查產出的 ARP 觀測、介面位址與介面名稱。涵蓋兩個平台、v2c 與 v3、有無 VRF、invalid 的列、secondary 位址、各種錯誤類別。實機擷取的回應之後直接加進這裡。

### 不自動化的部分

- 三種郵件軟體（Outlook、Gmail、Apple Mail）的版面與連結檢查。
- UI 的設計走查（PRD 第 10.8 節與 UI UX Pro Max 的交付前清單）。
- 實機驗證清單（開發規格第 12 節）。

### 既有的範例

這個儲存庫還沒有任何程式碼與測試，沒有可以沿用的範例。第一批測試要同時建立測試環境（啟動應用程式、模擬器與資料庫、控制時鐘的方式），之後的測試以它為範本。

## 範圍外

- IPv6。
- 產品內建的備份、還原與異地複製。
- DHCP／DNS 整合、位址自動配發。
- 非 Cisco 的設備；閘道在防火牆或路由器上的網段。
- 以 CLI、SSH 或裝置 API 取得 ARP。
- 任何外部的 OUI、Whois 或雲端查詢。
- NMS 類的效能監控與組態備份。
- 多租戶、跨園區的統一管理、重疊的位址空間。
- 主動探測（ping）裝置是否在線。
- 「MAC 接在哪個埠」。
- 郵件以外的通知管道。
- 以郵件連結在未登入的狀態下變更登記；網頁上的忘記密碼功能。
- 留到 Beta：衝突的批次處理與套用前預覽、檔案匯入登記、儀表板數字連動篩選、稽核紀錄的篩選與匯出、深色或暖沙主題、唯讀稽核角色。
- 之後另議：以網段為單位的檢視權限、多語系介面、同一園區並存兩種驗證來源。
