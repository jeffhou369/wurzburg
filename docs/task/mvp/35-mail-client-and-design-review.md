# 35 — 郵件軟體相容性檢查與設計走查

Status: ready-for-human
Blocked by: 28, 29, 30, 33

## 要做什麼

這一張需要人來做：有些東西自動化測試看不出來，要用眼睛在真實的環境裡檢查。

**一、三種信在三種郵件軟體的檢查**

把未登記彙整、未登記總表、到期催認（即將到期與已到期各一封，其中一封是合併多筆的）實際寄到測試信箱，分別在下列軟體開啟：

- Microsoft Outlook（桌面版）
- Gmail（網頁與手機 App）
- Apple Mail

每一封逐項檢查：

- 版面沒有破版，內容寬度與留白正常
- 明細表對齊，IP 與 MAC 沒有被自動變成連結或被截斷
- 主要按鈕看得到、點得動；按鈕下方的純文字連結也可用
- 連結帶到正確的頁面，沒有登入時先要求登入
- 狀態有文字，把畫面轉成灰階後仍然看得懂
- 切換成只顯示純文字時，內容與 HTML 對等
- 主旨與預覽文字正確，中文沒有亂碼
- 沒有被判為垃圾信；若有，記下原因

**二、UI 設計走查**

對照 PRD 第 10.8 節的檢查清單與 `design-system/ip-mgmt/MASTER.md` 的交付前清單，走過每一個畫面：登入、設定精靈、首頁（儀表板與表格）、IP 紀錄的 Sheet、網段、交換器、衝突、通知紀錄、稽核紀錄、設定。

重點：

- 與樣式包的三張官方截圖對照，整體觀感是否一致
- 沒有殘留元件庫的預設外觀，沒有散落的色碼
- 狀態不只靠顏色；離線的列是灰階但仍可讀
- 鍵盤可以操作全部功能，焦點看得到
- 文字對比足夠
- 在 375、768、1024、1440px 寬度下可用
- 錯誤訊息說的是人話，並告訴使用者可以怎麼做

## 驗收條件

- [ ] 每一種信在每一種郵件軟體的檢查結果都有紀錄，附螢幕截圖
- [ ] 已知的限制（例如 Outlook 不顯示圓角）寫進安裝文件
- [ ] 每一個畫面的走查結果都有紀錄
- [ ] 發現的缺失各自開成新的工作項目，並標明嚴重程度
- [ ] 沒有未追蹤的高嚴重缺失
