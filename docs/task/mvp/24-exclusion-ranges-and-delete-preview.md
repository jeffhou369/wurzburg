# 24 — 排除範圍，以及刪除前的預覽與確認

Status: ready-for-agent
Blocked by: 12

## 要做什麼

完成網段管理中會刪除 IP 紀錄的部分。位址一旦離開管理範圍，它的 IP 紀錄就直接刪除，而且不能復原，所以每一個這樣的操作都要先讓系統管理員看到後果。

**排除範圍**

- 納管的網段底下可以新增一到多段連續的位址，各附原因（DHCP、無線、其他）。
- 範圍內的位址視同不納管：不會有 IP 紀錄。
- 可以修改與移除排除範圍。移除後，範圍內的位址在下一輪被看到時重新建立為全新的未登記 IP 紀錄。

**會刪除 IP 紀錄的操作**

- 把納管的網段改為不納管
- 新增或擴大排除範圍
- 修正網段的 CIDR，或刪除手動新增的網段，使位址不再屬於任何納管的網段

**流程**

1. 預覽：系統回傳這個操作將刪除幾筆 IP 紀錄、其中幾筆有擁有者。
2. 確認對話框寫明這兩個數字，系統管理員再次確認才執行。沒有任何 IP 紀錄會被刪除時不需要確認。
3. 執行：刪除 IP 紀錄，連同它們的 ARP 觀測、衝突與通知去重狀態。
4. 稽核紀錄記下操作者、時間、網段或範圍、刪除的筆數；有擁有者的 IP 紀錄逐筆記下 IP、MAC、擁有者、擁有者信箱與到期日。

## 驗收條件

- [ ] 可以在納管的網段新增排除範圍；範圍超出網段、起訖顛倒或沒有原因時回 422
- [ ] 排除範圍內的位址在之後的輪次不會產生 IP 紀錄
- [ ] 預覽回傳的兩個數字正確
- [ ] 沒有經過確認，直接呼叫執行會被拒絕
- [ ] 預覽之後資料有變動（筆數不同）時，執行會被拒絕並要求重新預覽
- [ ] 確認後，受影響的 IP 紀錄與它們的 ARP 觀測、衝突、通知去重狀態都被刪除；不受影響的不變
- [ ] 上列四種操作都走同一套預覽與確認
- [ ] 稽核紀錄有筆數，且每一筆有擁有者的 IP 紀錄都有明細
- [ ] 網段重新納管或排除範圍移除後，位址再被看到時是全新的未登記 IP 紀錄
- [ ] 確認對話框清楚寫出將刪除幾筆、其中幾筆有擁有者，並說明無法復原
- [ ] 一般使用者不能執行這些操作
- [ ] 關鍵流程有瀏覽器測試：把一個有登記的網段改為不納管

## 邊界

- 接續第 12 張，修改同一個後端模組與網段頁。
- 測試需要的 IP 紀錄用資料擺設工具準備，不依賴第 13、18 張。
- 契約或資料庫結構有缺漏時，只做最小的補充，並在本檔案的 `## Comments` 記下。
