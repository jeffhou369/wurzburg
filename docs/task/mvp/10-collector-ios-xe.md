# 10 — 採集模組：IOS-XE

Status: ready-for-agent
Blocked by: 02, 06

## 要做什麼

實作採集模組：給它一筆 VRF 讀取設定，它對交換器做 SNMP 讀取，回傳 ARP 觀測、介面位址與介面名稱，或一個錯誤類別。這個模組是系統裡唯一知道 SNMP 與平台差異的地方。

這一張完成 IOS-XE，並建立兩個平台共用的部分：

- SNMP v2c 與 v3
- 以 v3 的 context 名稱或 v2c 的專屬 community 讀取非全域的 VRF
- ARP 表（MIB-II `ipNetToMediaTable`）：只取 IPv4，忽略類型為 invalid 的列，保留靜態或動態的類型
- 介面位址表與介面名稱，採用第 02 張摘要文件決定的 MIB 物件
- 錯誤分類：逾時、認證失敗、連線被拒、無資料
- 程式庫本身的重試要關閉；重試由輪詢排程負責
- 對同一台交換器的讀取要保守，並遵守逾時設定

另外提供一個命令列入口：對指定的交換器執行讀取，印出結果，並可把原始回應存成測試資料檔。設備到位時用它做實機驗證。

開始前查最新文件，決定 SNMP 程式庫與版本。

## 驗收條件

- [ ] 回放第 02 張的 IOS-XE 測試資料檔，產出的 ARP 觀測、介面位址、介面名稱與預期相符
- [ ] v2c 與 v3 都有測試
- [ ] 非全域的 VRF 以 context 名稱（v3）與專屬 community（v2c）讀取，都有測試
- [ ] invalid 的列被忽略；IPv6 的列被丟棄；靜態與動態的類型被保留
- [ ] secondary 位址出現在介面位址中
- [ ] ARP 觀測帶有介面名稱（例如 `Vlan10`）
- [ ] 四種錯誤類別各有測試
- [ ] 一次讀取只嘗試一次，沒有隱藏的重試
- [ ] 命令列入口可對 SNMP 模擬器執行，並把回應存成可回放的測試資料檔
- [ ] 憑證不出現在日誌與命令列的輸出中
- [ ] 文件註明：採集行為依據文件範例，尚未經實機確認

## 邊界

- 這張在輔助測試接縫驗證：輸入測試資料檔，檢查模組的輸出。
- 只修改採集模組；輪詢排程、網段與 IP 紀錄由其他工作項目處理。
- 介面有缺漏時，在本檔案的 `## Comments` 記下，並通知第 06 張的介面需要調整。
