# 05 — 完整的 API 契約與前端型別

Status: ready-for-agent
Blocked by: 01

## 要做什麼

一次寫好 MVP 全部資源的 API 描述，作為前後端唯一的契約。之後每個功能照著自己那一份描述實作，前端可以在後端完成之前就對著契約開發。

**資源**（每個資源一份描述檔，讓並行的工作項目各改各的）：工作階段（兩條登入路徑、登出）、目前的使用者、設定精靈的狀態、園區設定、驗證來源設定與測試、郵件設定與測試、交換器、VRF 讀取設定、同步（立即同步、輪詢狀態）、網段、排除範圍、未定前綴、IP 紀錄（查詢、變更事件、匯出）、登記動作、衝突（查詢、裁決）、通知紀錄與通知狀態的重設、OUI、稽核紀錄、系統管理員帳號、儀表板、健康檢查。

**共通的慣例**：

- 清單一律由伺服端分頁、排序與篩選；IP 表格與匯出共用同一組篩選條件。
- 會刪除 IP 紀錄的變更分成兩步：預覽（回傳將刪除的筆數與其中有擁有者的筆數）與確認執行。
- 登記動作接受一組 IP 紀錄或「目前篩選結果的全部」，回傳逐筆的成功或失敗與原因；單筆是它的特例。
- 未登入回 401，沒有權限回 403，狀態不允許該動作回 409，輸入不合法回 422；錯誤回應有一致的格式。
- 任何回應都不包含 secret；設定類的回應只說明某個 secret「已設定」。
- IP 紀錄的回應同時帶在線狀態、登記狀態、是否即將到期與是否有衝突，讓介面能組出「在線 · 未登記」這類文字。

**前端**：由描述檔產生 API 型別，並提供開發用的模擬回應，讓頁面在後端完成前可以運作。
