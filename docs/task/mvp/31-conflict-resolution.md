# 31 — 衝突的裁決

Status: ready-for-agent
Blocked by: 25

## 要做什麼

讓系統管理員能把一筆衝突處理掉。在衝突頁打開一筆衝突的 Sheet，看到每個 MAC 分別出現在哪台交換器與哪個 VRF、首次與最近見到的時間，然後選擇一種裁決，並可加上說明。

| 裁決 | 結果 |
| --- | --- |
| 採信新的 MAC，登記保留 | 採信 MAC 更新，衝突已解消 |
| 採信新的 MAC，登記釋放 | 採信 MAC 更新，IP 紀錄回到未登記，衝突已解消 |
| 維持原本的 MAC | 衝突進入處理中 |

有多個 MAC 並存時，系統管理員先選定要採信哪一個。

**處理中的規則**

- 採信 MAC 與登記都不變。
- 另一個 MAC 繼續被看到時不重複開衝突，也不計入「未處理」的數字。
- 另一個 MAC 連續達到離線判定輪數不再出現後，衝突自動變成已解消。
- 系統管理員可以重新打開處理中的衝突，改選另外兩種裁決。

IP 紀錄沒有擁有者時（並存的情況），不顯示與登記有關的選項。

批次裁決與套用前預覽屬於 Beta。

## 驗收條件

- [ ] 裁決為「採信新的 MAC，登記保留」後，採信 MAC 更新，擁有者不變，衝突已解消
- [ ] 裁決為「採信新的 MAC，登記釋放」後，採信 MAC 更新，IP 紀錄是未登記，衝突已解消
- [ ] 裁決為「維持原本的 MAC」後，衝突是處理中，採信 MAC 與登記不變
- [ ] 處理中的衝突，另一個 MAC 繼續出現時不產生新的衝突，側欄的未處理數字不增加
- [ ] 處理中的衝突，另一個 MAC 連續兩輪成功讀取都不再出現後，自動已解消
- [ ] 處理中的衝突可以重新打開並改成另外兩種裁決
- [ ] 已解消的衝突不能再裁決
- [ ] 已解消後，同一個 IP 再次出現不一致時開一筆新的衝突
- [ ] 並存且沒有擁有者時，只能選擇採信哪一個 MAC 或維持原本的
- [ ] 一般使用者呼叫裁決的 API 回 403，畫面上也沒有裁決的按鈕
- [ ] 每一次裁決都寫入稽核紀錄，帶裁決的內容、說明與變更前後的採信 MAC
- [ ] 關鍵流程有瀏覽器測試：系統管理員裁決一筆衝突

## 邊界

- 接續第 25 張，修改同一個後端模組與衝突頁。
- 測試以「送入一輪讀取結果」驅動，衝突與有擁有者的 IP 紀錄用資料擺設工具準備。
- 釋放登記沿用第 18 張的規則；第 18 張尚未完成時，這裡只做它需要的最小部分並在 `## Comments` 記下。
- 契約或資料庫結構有缺漏時，只做最小的補充，並在本檔案的 `## Comments` 記下。
