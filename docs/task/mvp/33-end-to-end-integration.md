## 要做什麼

第 07 到 32 張是各自獨立開發與驗證的：測試直接擺好前置資料或直接送入一輪的讀取結果，沒有真的讓上游的功能跑一遍。這一張把真正的整條路徑接起來，確認各功能合在一起時是對的，並修掉合起來才出現的問題。

整套測試只用主要測試接縫，而且不再擺前置資料：從一套空的系統開始，外部系統全部是模擬器（SNMP 模擬器回放測試資料檔、模擬的 AD 或 RADIUS、收信用的測試郵件伺服器），所有狀態都由 API 的操作與時鐘的推進產生。

**要走通的情境**

1. 全新安裝：以環境變數的帳密登入、改密碼、走完設定精靈（驗證來源、郵件、第一台交換器、把一個網段設為納管）。
2. 採集到表格：時鐘前進一輪後，模擬交換器上的位址出現在首頁表格，閘道位址不在其中，儀表板的數字與表格一致，廠商有顯示。
3. 未登記彙整：到了整點，系統管理員收到一封列出這些位址的信；下一個小時沒有新的位址，不再收到。
4. 登記：一般使用者以組織帳號登入，登記其中幾筆（含一次批次登記）；這些位址不再出現在之後的未登記彙整。
5. 離線與恢復：模擬交換器不再回報某個位址，兩輪之後它變成離線；重新回報後恢復在線。讀取失敗的輪次不造成離線。
6. 衝突：已登記的位址換了 MAC，出現一筆衝突；系統管理員裁決後已解消。未登記的位址換了 MAC，沒有衝突，但會再出現在未登記彙整。
7. 到期：時鐘前進到到期前 14 天，擁有者收到催認信；批次重新確認後不再收到。另一筆不處理，收完全部的催認後維持已到期，最後一次有副本給系統管理員。
8. 未登記總表：到了每週的寄送時間，系統管理員收到仍未登記的總表。
9. 排除範圍與不納管：劃出排除範圍後，範圍內的 IP 紀錄在確認後被刪除，稽核紀錄有明細；把網段改為不納管亦同。
10. 自動清除：未登記且離線的位址在 90 天後消失，已登記的還在。
11. 匯出：匯出的 Excel 與畫面上的篩選結果一致。
12. 兩個平台與 VRF：IOS-XE 與 NX-OS 各一台、其中一台有兩筆 VRF 讀取設定，全部的位址都出現；其中一筆 VRF 讀取設定失敗時，其他的不受影響。
13. 故障隔離：郵件伺服器或驗證來源中斷時，採集與網頁照常運作，系統管理員仍可登入。

**另外要檢查的**

- 逐一看過第 07 到 32 張檔案的 `## Comments`，處理各張記下的契約與資料庫結構的補充，確認 API 描述、資料庫結構與實作三者一致。
- 掃描日誌、API 回應、稽核紀錄與寄出的信，確認沒有任何 secret。
- 以設計目標的規模（50 台交換器、200 筆 VRF 讀取設定、25,000 筆 IP 紀錄）跑一輪，確認能在 3 分鐘內完成，首頁在可接受的時間內顯示。
