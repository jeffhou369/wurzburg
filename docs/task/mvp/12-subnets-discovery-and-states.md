# 12 — 網段的發現與三種狀態

Status: ready-for-agent
Blocked by: 03, 05, 06

## 要做什麼

讓系統從一輪讀取結果的介面位址中發現網段，並讓系統管理員在「網段」頁決定每個網段要不要管。這是處理管線中「管理範圍」那一步的寫入部分。

- 每個 L3 介面上的位址與遮罩構成一個網段。系統不從主機位址推測遮罩。
- 新發現的網段是待檢視。側欄的「網段」顯示待檢視的數量。
- 系統管理員可以把網段設為納管，或設為不納管並選擇原因（DHCP、無線、其他），可加說明。待檢視只是初始狀態，做過決定後只能在納管與不納管之間切換。
- 多台交換器回報同一個 CIDR 時是同一個網段。
- 介面位址表裡的位址記為該網段的閘道位址，顯示在網段的詳細資料中。
- 系統管理員可以手動新增網段，也可以修正網段的 CIDR。
- 交換器上已經不存在的網段不自動刪除，標示「來源已消失」。

網段改為不納管、修正 CIDR 或刪除手動新增的網段而導致 IP 紀錄被刪除的流程（預覽、確認、稽核明細），由第 24 張完成。這一張在這些操作會影響既有 IP 紀錄時先拒絕並說明原因。

## 驗收條件

- [ ] 送入一輪帶有介面位址的讀取結果後，對應的網段以待檢視出現
- [ ] 同一個 CIDR 由兩台交換器回報時只有一個網段，兩個閘道位址都列在它底下
- [ ] secondary 位址構成的網段也被發現
- [ ] 側欄顯示待檢視的數量，做完決定後數量減少
- [ ] 設為不納管時沒有選原因會回 422
- [ ] 已做過決定的網段不能改回待檢視
- [ ] 可以手動新增網段；CIDR 格式錯誤或與既有網段完全相同時回 422
- [ ] 來源不再回報的網段被標示「來源已消失」，狀態不變
- [ ] 網段的詳細資料顯示 CIDR、來源的交換器與 VRF、閘道位址、狀態與原因
- [ ] 一般使用者呼叫變更的 API 回 403
- [ ] 狀態變更寫入稽核紀錄
- [ ] CIDR 以等寬字顯示；待檢視的網段有醒目的提示

## 邊界

- 測試以「送入一輪讀取結果」驅動，不依賴採集與輪詢排程。
- 位址歸屬的查詢由第 06 張提供，這張不重寫。
- 只修改本功能自己的後端模組、頁面、介面文字與自己那一份 API 描述；共用的檔案不要改。
- 契約或資料庫結構有缺漏時，只做最小的補充，並在本檔案的 `## Comments` 記下。
