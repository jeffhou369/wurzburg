# 27 — 批次操作

Status: ready-for-agent
Blocked by: 15, 18

## 要做什麼

讓人一次處理多筆登記，不必重複開幾十次 Sheet。

在首頁的 IP 表格勾選多筆（或一次勾選目前篩選結果的全部）後，出現批次動作列：

- **批次登記**：填一次擁有者信箱、裝置類型與備註，套用到所有勾選的未登記 IP 紀錄；執行的人成為擁有者。
- **批次重新確認**：勾選的登記全部把到期日延到當天加上有效期。
- **批次釋放**。
- **批次改派**（僅系統管理員）：把勾選的登記改派給同一個帳號。

規則：

- 權限照單筆的規則逐筆判斷。沒有權限或狀態不允許的那幾筆略過，其餘照常執行。
- 執行後顯示結果：成功幾筆、略過幾筆，並列出略過的每一筆與原因。
- 釋放與改派在執行前要確認，並寫明筆數。
- 每一筆的變更都寫入稽核紀錄，並標示是批次操作。

## 驗收條件

- [ ] 勾選多筆未登記的 IP 紀錄後批次登記，全部成為已登記，擁有者是執行的人
- [ ] 勾選的項目中夾雜已有擁有者的，那幾筆被略過並說明原因，其餘成功
- [ ] 一般使用者批次重新確認時，不是自己的登記被略過並說明原因
- [ ] 「全選篩選結果」後執行，作用到全部符合的筆數而不只是當頁
- [ ] 批次改派對一般使用者不顯示，直接呼叫 API 回 403
- [ ] 批次釋放與改派在執行前有確認，寫明筆數
- [ ] 結果畫面列出成功與略過的筆數，以及每一筆略過的原因
- [ ] 擁有者信箱格式錯誤時整批不執行，回 422
- [ ] 每一筆變更在稽核紀錄有一筆，並標示為批次操作
- [ ] 一次處理 1,000 筆能在可接受的時間內完成
- [ ] 關鍵流程有瀏覽器測試：從到期清單全選後批次重新確認

## 邊界

- 沿用第 18 張的登記動作（它本來就接受一組 IP 紀錄），不另外實作一份權限規則。
- 沿用第 15 張的勾選與篩選條件。
- 只修改表格的批次動作列與批次相關的對話框、介面文字；後端只在登記動作不足時做最小的補充。
- 契約或資料庫結構有缺漏時，只做最小的補充，並在本檔案的 `## Comments` 記下。
