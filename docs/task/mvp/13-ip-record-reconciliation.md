# 13 — IP 紀錄的整併

Status: ready-for-agent
Blocked by: 03, 05, 06

## 要做什麼

把每一輪讀取結果裡的 ARP 觀測整併進 IP 紀錄。這是處理管線中「狀態整併」那一步的核心，也是「在線」與「離線」的來源。

- **建立**：ARP 觀測的 IP 落在納管的網段、不在排除範圍內、不是閘道位址時，建立 IP 紀錄（已存在就更新）。第一次見到的 MAC 成為採信 MAC。
- **多來源**：系統為每一組「IP 紀錄 × VRF 讀取設定」保存一筆目前的 ARP 觀測。一筆 IP 紀錄可以同時被多台交換器看到。
- **離線判定**：某筆 VRF 讀取設定成功讀取、卻沒有回報某個原本看得到的 IP 時，那筆觀測的未見輪數加一；達到離線判定輪數（預設 2）時移除。讀取失敗的那一輪不計。IP 紀錄還有任何一筆觀測就是在線，全部移除後是離線；任一來源重新看到就立刻恢復在線。
- **變更事件**：記下首次見到、在線與離線的切換。
- **未定前綴**：IP 不落在任何已知網段的 ARP 觀測，列入未定前綴清單（IP、MAC、交換器、VRF、介面），不建立 IP 紀錄。
- **廠商**：建立與更新 MAC 時，經由 OUI 查詢的介面填入廠商名稱。

畫面：

- IP 紀錄 Sheet 的「觀測與歷程」分頁：目前在哪些交換器、哪個 VRF、哪個介面上被看到，各自的最後見到時間，以及變更歷程。並說明「在線」的意思：交換器的 ARP table 裡仍有這個位址，裝置實際離開後要等交換器的 ARP 逾時才會變成離線。
- 網段頁底下的「未定前綴」清單。

MAC 與採信 MAC 不同時的處理（衝突，或未登記時直接更新）由第 25 張完成。這一張遇到這種情況先不改採信 MAC。

## 驗收條件

- [ ] 納管網段內的 ARP 觀測產生 IP 紀錄；待檢視、不納管網段內的不產生
- [ ] 排除範圍內的位址與閘道位址不產生 IP 紀錄
- [ ] 同一個 IP 由兩筆 VRF 讀取設定回報時只有一筆 IP 紀錄、兩筆 ARP 觀測
- [ ] 一輪沒看到時仍是在線；連續兩輪成功讀取都沒看到才變成離線
- [ ] 兩個來源中只有一個不再回報時，IP 紀錄維持在線
- [ ] 讀取失敗的輪次不增加未見輪數
- [ ] 離線後再次被看到時立刻恢復在線，最後見到時間更新
- [ ] 離線判定輪數改成其他值後，行為跟著改變
- [ ] 首次見到、變為離線、恢復在線各產生一筆變更事件
- [ ] 不屬於任何網段的 ARP 觀測出現在未定前綴清單；為它新增網段並納管後，下一輪它不再出現在清單
- [ ] 「觀測與歷程」分頁顯示所有來源與歷程，並有「在線」的說明文字
- [ ] 25,000 筆 ARP 觀測的一輪以批次寫入，能在合理時間內完成

## 邊界

- 測試以「送入一輪讀取結果」驅動，網段與排除範圍用資料擺設工具準備；不依賴採集、輪詢排程與第 12 張。
- 位址歸屬的查詢與狀態的推算由第 06 張提供，這張不重寫。
- 只修改本功能自己的後端模組、Sheet 的「觀測與歷程」分頁、未定前綴清單、介面文字與自己那一份 API 描述。
- 契約或資料庫結構有缺漏時，只做最小的補充，並在本檔案的 `## Comments` 記下。
