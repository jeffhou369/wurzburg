# 36 — 實機驗證

Status: ready-for-human
Blocked by: 10, 23

## 要做什麼

這一張需要人來做，而且要等借到實體設備。採集模組是依據文件與公開範例開發的，這裡用真的交換器確認那些假設。

**需要準備**

- IOS-XE 與 NX-OS 的交換器各至少一台，上面有實際的 L3 介面與主機
- 至少一台設有非全域的 VRF
- 唯讀的 SNMP 帳號：v2c 與 v3 各一組；VRF 的 context 對應已在交換器端設好
- 可以的話，一組 HSRP 或 VRRP

**做法**

用採集模組的命令列入口，對每一台交換器、每一種 SNMP 版本、每一個 VRF 各執行一次讀取，把原始回應存成測試資料檔，然後逐項確認：

| 要確認的事 | 影響 |
| --- | --- |
| 兩個平台的 ARP 表各自回傳什麼 | 採集的基礎 |
| v2c 用各 VRF 專屬的 community、v3 用 context 名稱，是否都讀得到各 VRF 的 ARP | VRF 讀取設定 |
| 介面位址表是否完整，secondary 位址是否包含在內 | 網段的發現 |
| 交換器自己的介面位址與 HSRP／VRRP 虛擬位址在 ARP 表裡如何呈現 | 閘道位址 |
| 兩個平台的 ARP 逾時預設值 | 「在線」的說明文字 |
| 介面名稱是否讀得到、與 ARP 的介面索引是否對得上 | 介面的顯示 |
| 讀取數千筆 ARP 實際需要多久 | 並行數與逾時 |

第 02 張摘要文件中列為「找不到依據」的項目優先確認。

接著把系統實際接上這些交換器跑一段時間，確認首頁看到的位址、網段與在線狀態符合現場。

## 驗收條件

- [ ] 上表每一項在兩個平台上都有確認結果，寫成紀錄
- [ ] 每一次讀取的原始回應都存成測試資料檔並加進採集模組的測試，註明設備型號與作業系統版本
- [ ] 測試資料檔中的 community、主機名稱、真實的 MAC 與 IP 已視需要去識別化
- [ ] 實機的行為與文件範例不同的地方，各自開成新的工作項目
- [ ] 系統實際接上交換器後，位址、網段、閘道位址與在線狀態符合現場
- [ ] 安裝文件中「尚未經實機確認」的註記依結果更新或移除
- [ ] 兩個平台的 ARP 逾時與建議值寫進安裝文件
