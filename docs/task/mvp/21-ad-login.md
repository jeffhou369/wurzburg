# 21 — AD 登入

Status: resolved
Blocked by: 07

## 要做什麼

讓園區可以選擇 AD 作為驗證來源，一般使用者用 AD 的帳密登入。

- 實作驗證來源介面的 AD 版本：以 LDAPS 連線驗證帳密。
- 設定頁「驗證來源」底下的 AD 表單：伺服器位址與埠、查詢用的帳號與密碼、搜尋的起點、帳號／信箱／顯示名稱各對應哪個屬性、允許登入的群組（留空代表所有 AD 帳號都能登入）。
- 查詢用的密碼加密保存，儲存後不回顯。
- 「測試」按鈕：以一組帳密試著登入，顯示成功（並列出取得的信箱與顯示名稱）或失敗的原因。
- 登入成功時取得信箱與顯示名稱，存在帳號上；之後每次登入更新。
- 生產預設要求加密連線；選擇不加密時要有明確的警告。

開始前查最新文件，決定 LDAP 程式庫與版本。

## 驗收條件

- [x] 對模擬的 AD，正確的帳密可以登入，錯誤的帳密不行
- [x] 登入後帳號上有從目錄取得的信箱與顯示名稱
- [x] 設定了允許的群組後，不在群組裡的帳號不能登入；留空時都能登入
- [x] 屬性的對應可以修改並生效
- [x] 「測試」成功時顯示取得的信箱與顯示名稱，失敗時顯示可理解的原因
- [x] AD 連不上時，一般使用者看到清楚的訊息；系統管理員仍然可以登入
- [x] 查詢用的密碼在 API 回應、日誌與稽核紀錄中都讀不到
- [x] 使用者輸入的帳號不會被當成查詢語法的一部分（防注入）
- [x] 設定的變更寫入稽核紀錄，且不含密碼
- [x] 選擇不加密連線時，設定頁有警告

## Comments

已完成 21 — AD 登入：
- 採用官方推薦 `github.com/go-ldap/ldap/v3` 實作 `internal/authsource/ad.go`，支援 `ldaps://` 與 StartTLS。
- 搜尋時透過 `ldap.EscapeFilter` 跳脫帳號字串，防止 LDAP 注入攻擊。
- 支援繫結搜尋特定 `memberOf` 群組驗證，登入時自動擷取 `mail` 與 `displayName`。
- 前端 `auth-settings.component.ts` 提供 AD 表單與即時測試連線按鈕。
