# 28 — 未登記彙整

Status: ready-for-agent
Blocked by: 19

## 要做什麼

每小時把新出現的、沒有人負責的位址告訴系統管理員，而且同一個位址只講一次。

- 每小時整點（園區的時區）執行。
- 納入的條件：IP 紀錄在線、未登記，而且它的去重鍵還沒有處於「已通知」。去重鍵是 `unreg|{ip}|{採信 MAC}`。
- 有新增項目時，寄一封未登記彙整給系統管理員收件清單；沒有新增就不寄。
- 成功寄出後才把這些去重鍵標為已通知。寄送失敗的不得標為已通知，下一次會再納入。
- 已通知的狀態在下列情況解除：完成登記、IP 紀錄被刪除、系統管理員手動重設。裝置離線不解除。
- 未登記的 IP 換了 MAC 後去重鍵不同，會再被列為新增一次。
- 同一個小時、同一批項目不得重複寄送。

信的內容（使用第 19 張的共用版面）：

- 主旨：`[Würzburg] 未登記在線位址彙整（新增 N 筆，日期時間與時區）`
- 摘要：新增待處理的筆數、累計仍未登記（已通知未解除）的筆數、涉及的網段數與交換器數
- 明細表：狀態（文字）、IP、MAC、廠商、網段、交換器、介面、首次見到、最近見到。最多列 50 筆，超過時註明其餘請到系統檢視
- 主要按鈕：連到已篩選為「在線 · 未登記」的清單，需要登入
- 頁尾：為何收到、每小時一次且已通知的不會重複、請勿直接回覆、時區

系統管理員可以在通知紀錄頁手動重設某個位址的通知狀態。

## 驗收條件

- [ ] 整點時有新的在線且未登記的 IP 紀錄，就寄出一封給收件清單上的每個人
- [ ] 沒有新增項目時不寄，即使有累計未登記的
- [ ] 同一個 IP 與 MAC 在下一個小時不會再被列為新增
- [ ] 離線的未登記 IP 紀錄不被納入；之後變回在線時，沒通知過的才納入
- [ ] 通知過的 IP 離線再上線，不會再被列為新增
- [ ] 未登記的 IP 換了 MAC 後，再被列為新增一次
- [ ] 寄送失敗時去重鍵沒有被標為已通知，下一次仍會納入
- [ ] 完成登記後，那個位址的已通知狀態解除；之後釋放並仍在線時，會再被列為新增
- [ ] 手動重設後，那個位址在下一次彙整重新出現
- [ ] 超過 50 筆時明細只列 50 筆並有註明，摘要的筆數仍是實際數字
- [ ] 信有純文字與 HTML，兩者的摘要、明細與連結對等
- [ ] 連結帶到已篩選的清單，沒有登入時先要求登入
- [ ] 信中沒有任何可以直接寫入的權杖
- [ ] 每次寄送在通知紀錄有一筆

## 邊界

- 測試需要的 IP 紀錄與通知狀態用資料擺設工具準備，並用測試控制的時鐘觸發；不依賴採集與整併。
- 與第 29、30 張並行：只修改未登記彙整自己的模組與範本。
- 契約或資料庫結構有缺漏時，只做最小的補充，並在本檔案的 `## Comments` 記下。
