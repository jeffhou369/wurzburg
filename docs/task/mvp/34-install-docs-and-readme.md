# 34 — 安裝文件與 README.md

Status: resolved

## 要做什麼

寫給安裝人員與系統管理員的文件，讓一個沒有參與開發的人能在自己的園區把 Würzburg 裝起來並開始使用。文件用繁體中文。

**`README.md`**：這個專案是什麼、為誰而做、一段話的運作方式、最短的啟動步驟、其他文件在哪裡、授權與上游樣式的出處。

**安裝文件**

1. **部署前提條件**
   - 各網段的 L3 閘道在 Cisco 交換器上，平台為 IOS-XE 或 NX-OS；閘道在防火牆或路由器上的網段看不到
   - 園區內的 IPv4 位址不重疊，包含不同 VRF 之間；一個園區裝一套
   - 交換器已開啟唯讀的 SNMP；有 VRF 時，交換器端要先替每個 VRF 設好對應（兩個平台各自的設定方式）
2. **安裝步驟**：需要的軟體、取得與啟動、每一個環境變數的說明（包含第一個系統管理員的帳號與初始密碼、secret 的加密金鑰）。
3. **首次登入**：改密碼、設定精靈的每一步需要準備什麼；提醒在首次登入後把初始密碼從設定檔移除。
4. **啟用 HTTPS**：如何使用選用的設定；在啟用之前只能在受信任的內網使用，以及明文傳輸的風險。
5. **「在線」的意思**：在線代表交換器的 ARP table 裡仍有這個位址；裝置離開後要等 ARP 逾時才會變成離線；兩個平台的預設逾時；需要時如何調短。
6. **資料與備份**：產品不內建備份。刪除 Compose 的 volume 會永久遺失登記資料；加密金鑰遺失時，所有 secret 要重新輸入。附上以 volume 快照或資料庫匯出自行備份的範例，並註明這是營運側的做法，不是產品的保證。
7. **日常維運**：忘記系統管理員密碼時的重設指令、更新 OUI 資料、查看日誌、升級的步驟。
8. **驗證來源的注意事項**：AD 要用加密連線；RADIUS 伺服器要允許本系統的來源 IP 以及 PAP 的限制；上線後更改驗證來源的後果。
9. **郵件軟體的已知限制**：例如 Outlook 不顯示圓角。
10. **目前的限制**：採集行為依據文件範例，尚未經實機確認（實機驗證完成後移除這一段）；不支援的項目。
