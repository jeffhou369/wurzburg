# 29 — 未登記總表

Status: ready-for-agent
Blocked by: 19

## 要做什麼

未登記彙整只在有新增項目時寄出，所以通知過一次、之後一直沒有人登記的位址，不會再出現在任何信裡。未登記總表每週把這些累積的項目列給系統管理員，避免它們被遺忘。

- 每週執行一次，寄送時間是設定值，預設週一 09:00（園區的時區）。系統管理員可以在設定頁調整。
- 納入的條件：IP 紀錄在線、未登記，而且它的去重鍵處於「已通知」。
- 有項目時寄一封給系統管理員收件清單；沒有項目就不寄。
- 未登記總表不改變任何通知狀態。
- 同一週不重複寄送。

信的內容（使用第 19 張的共用版面，版面沿用未登記彙整）：

- 主旨：`[Würzburg] 仍未登記的在線位址總表（共 N 筆，日期與時區）`
- 摘要：仍未登記的筆數、涉及的網段數與交換器數、其中最早通知的是多久以前
- 明細表：狀態（文字）、IP、MAC、廠商、網段、交換器、介面、首次見到、首次通知的時間。最多列 50 筆，超過時註明其餘請到系統檢視
- 主要按鈕：連到已篩選為「在線 · 未登記」的清單，需要登入
- 頁尾：為何收到、每週一次、請勿直接回覆、時區

## 驗收條件

- [ ] 到了設定的時間，有已通知且仍在線、未登記的 IP 紀錄，就寄出一封
- [ ] 沒有符合的項目時不寄
- [ ] 還沒被未登記彙整通知過的 IP 紀錄不出現在總表
- [ ] 已登記、離線或已被刪除的不出現在總表
- [ ] 寄出總表後，通知狀態沒有任何變化
- [ ] 修改寄送時間後，下一次依新的時間寄出
- [ ] 同一週不會寄出第二封
- [ ] 超過 50 筆時明細只列 50 筆並有註明
- [ ] 信有純文字與 HTML，兩者資訊對等
- [ ] 每次寄送在通知紀錄有一筆
- [ ] 一般使用者不能修改寄送時間

## 邊界

- 測試需要的 IP 紀錄與通知狀態用資料擺設工具準備，並用測試控制的時鐘觸發；不依賴第 28 張。
- 與第 28、30 張並行：只修改未登記總表自己的模組、範本與設定頁中自己的子頁。
- 契約或資料庫結構有缺漏時，只做最小的補充，並在本檔案的 `## Comments` 記下。
