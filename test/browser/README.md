# 瀏覽器關鍵流程

以 Playwright 對一套隔離環境走第 42 張工作項目的流程。目前有 10 個依序執行的測試：登入（含初次改密碼、登入後導向與登入卡片版面）、設定精靈、外殼導覽、一般郵件設定、工作臺狀態文字、組織帳號登入、單筆與批次登記、批次重新確認、裁決衝突、把網段改為不納管。

外殼情境驗證桌面 264／64px 收合與偏好保留、滑鼠／鍵盤提示、目前頁面標示、右上主題與登出、側欄底部身分、375px 手機抽屜及焦點還原、900／901px 斷點與減少動態效果。一般郵件設定情境先存入錯誤的合成密碼，再只在畫面填入正確值後直接測試，確認新密碼先儲存並通過 Mailpit 驗證；重新載入後留白測試仍使用已儲存值。

2026-11-15 本機一次執行紀錄：10 個流程全部通過，Playwright 約 26.1 秒，含模擬器與資料庫啟停的 Go 測試約 32.4 秒；這是單次開發機測值，不是效能保證。手機檢查只涵蓋上述關鍵情境，不代表所有功能頁或跨瀏覽器版面已完整驗收，也不等於真實 Gmail 寄送或人類郵件用戶端驗收。徽章的完整數量與 `99+` 縮寫另有 Angular 元件輔助測試，不宣稱此瀏覽器情境驗證了所有非零徽章的視覺狀態。

環境是真實的 Go 後端（內嵌剛建置的前端）、MariaDB，以及模擬的 SNMP、LDAP、郵件伺服器。不攔截網路、不偽造 API 回應、不使用測試身分標頭。容器是拋棄式的，不會動到既有部署。

## 執行

需要 Docker、Go、Node.js。第一次：

```sh
cd test/browser
npm ci
npx playwright install chromium
```

之後在儲存庫根目錄：

```sh
test/browser/run.sh
```

`run.sh --hold` 只啟動環境並保持運作，供手動看畫面；位址寫在 `test/browser/.env.json`，刪除該檔案即結束。

CI（`.github/workflows/code-quality.yml` 的 Browser Flows）會執行同一套流程。
